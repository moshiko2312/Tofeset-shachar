# משחק התופסת · שכב״ג שחר

אתר למשחק תופסת שרשרת של שכב״ג שחר (צופים).

- כל ילד נרשם עם שם וקוד אישי בן 4 ספרות.
- הסדר נקבע לפי סדר ההרשמה: כל אחד תופס את מי שאחריו, והאחרון תופס את הראשון.
- תופסים? מצלמים את מי שנתפס דרך האתר. הנתפס מקבל הודעה ומאשר.
- 🧣 מי שחובש עניבת צופים אי אפשר לתפוס. הנתפס יכול לדחות תפיסה עם "הייתי עם עניבה".
- מי שתפס מקבל את המטרה של מי שנתפס. האחרון שנשאר מנצח.
- כל השרשרת גלויה לכולם. במחלוקת המדריך רואה את התמונה ומכריע.

## מבנה

| קובץ | מה יש בו |
|---|---|
| `index.html` | כל האתר: ילדים, שרשרת, חוקים ומסך מדריך (`#admin`) |
| `config.js` | הכתובת והמפתח של Supabase |
| `supabase/setup.sql` | הטבלאות וחוקי המשחק במסד הנתונים |
| `logo.svg`, `logo-full.svg` | הלוגו של שכב״ג שחר |

בלי `config.js` מלא, האתר עובד **במצב הדגמה**: הנתונים נשמרים רק בטלפון אחד. קוד מדריך בהדגמה: `1234`.

## הקמה (פעם אחת, בערך 10 דקות)

### 1. Supabase (מסד הנתונים, חינם)
1. נכנסים ל-[supabase.com](https://supabase.com), יוצרים פרויקט חדש (אזור קרוב, למשל Frankfurt).
2. פותחים את `supabase/setup.sql`, ומחליפים את `shachar2026` בקוד המדריך שרוצים.
3. ב-Supabase: **SQL Editor → New query**, מדביקים את כל הקובץ ולוחצים **Run**.
4. ב-**Project Settings → API** מעתיקים את **Project URL** ואת המפתח **anon** (או **publishable**).
5. מדביקים את שניהם ב-`config.js`.

המפתח הזה מיועד להיות ציבורי. אי אפשר לקרוא או לשנות את הטבלאות ישירות, רק דרך פונקציות המשחק שבודקות קוד אישי או קוד מדריך.

### 2. GitHub Pages
1. ב-repo: **Settings → Pages → Build and deployment**.
2. Source: **Deploy from a branch**, Branch: `main`, תיקייה: `/ (root)`, **Save**.
3. אחרי דקה האתר עולה בכתובת `https://<user>.github.io/<repo>/`.

### 3. ביום המשחק
1. המדריך נכנס ל-`<כתובת האתר>#admin` עם קוד המדריך.
2. (לא חובה) בהגדרות קובעים **קוד הצטרפות**, כדי שרק מי שקיבל את הקישור יוכל להירשם.
3. שולחים לילדים את הקישור מהמסך (יש כפתור וואטסאפ).
4. כשכולם רשומים: **▶ התחלת המשחק**. ההרשמה נסגרת, ומדריך עדיין יכול להוסיף ילד ידנית לסוף הרשימה.

## מסך המדריך
- אישור או דחייה של תפיסות, כולל צפייה בתמונה.
- מחלוקות: תפיסות שהנתפס דחה (למשל בגלל עניבה). אפשר לאשר בכל זאת.
- הוספה ומחיקה של ילדים, החזרת ילד למשחק, איפוס קוד אישי.
- סבב חדש עם אותם ילדים, או איפוס מלא.
- מחיקת כל התמונות בסוף המשחק.

## פרטיות
התמונות לא גלויות לכולם: רק הילד שצולם (כדי לאשר) והמדריך רואים אותן. מומלץ למחוק את התמונות בסוף המשחק מתוך מסך המדריך.
